Log-Level

Jede Ausgabe hat einen Schweregrad, der Farbe und Kompilierbarkeit bestimmt:

LevelFarbeWann aktiv
logError...rotimmer aktiv
logWarning...gelbimmer aktiv
logInfo...keineimmer aktiv
logDebug...cyannur wenn OPENKNX_DEBUG im Build gesetzt ist bedingt (sonst No-Op)
logTrace...cyannur wenn OPENKNX_TRACE gesetzt und checkTrace() den Prefix durchlässt bedingt

Die 4 Varianten pro Level

Für jeden Level (hier am Beispiel Debug) gibt es vier Formen, je nach Aufrufkontext und Datentyp:

MakroBeispielWann verwenden
logDebug(prefix, message, ...) logDebug("1BS", "State: %u", state); Freie Funktionen (kein this, z. B. inline void handle_1BS(...)) — Prefix muss man selbst als String angeben.
logDebugP(message, ...) logDebugP("State: %u", state); Klassenmethoden, deren Klasse eine logPrefix()-Methode besitzt (von OpenKNX::Base / OpenKNX::Channel abgeleitet) — Prefix kommt automatisch aus logPrefix().
logHexDebug(prefix, data, size) logHexDebug("1BS", buf, 4); Byte-Array als Hex-Dump (zweistellig, mit führender Null), freie Funktion.
logHexDebugP(data, size) logHexDebugP(buf, 4); Byte-Array als Hex-Dump, Klassenmethode mit logPrefix().
Faustregel: Endet die Methode/Funktion nicht auf einer Klasse mit logPrefix(), muss die Nicht-P-Variante mit explizitem Prefix-String verwendet werden — sonst schlägt der Compile mit Use of undeclared identifier 'logPrefix' fehl.

Alle 20 Makros im Überblick

Dieselben 4 Varianten existieren für alle 5 Level, macht 20 Makros insgesamt:

logError      logErrorP      logHexError      logHexErrorP
logWarning    logWarningP    logHexWarning    logHexWarningP
logInfo       logInfoP       logHexInfo       logHexInfoP
logDebug      logDebugP      logHexDebug      logHexDebugP
logTrace      logTraceP      logHexTrace      logHexTraceP

Hilfsmakros

  • logIndentUp() / logIndentDown() — erhöht/verringert die Einrücktiefe nachfolgender Log-Zeilen, z. B. um verschachtelte Abläufe optisch zu gliedern.
  • logIndent(x) — setzt die Einrücktiefe direkt auf x.
  • logBegin() / logEnd() — exklusiver Lock für zusammenhängende Mehrzeilen-Ausgaben (Schutz bei Dual-Core-Zugriff).

Low-Level-API (openknx.logger.*)

Falls die Makros nicht reichen, kann direkt auf die Logger-Instanz zugegriffen werden:

  • log(message) — Ausgabe ohne Prefix/Farbe.
  • logWithPrefix(prefix, message) — Ausgabe mit explizitem Prefix, ohne printf-Formatierung.
  • logWithPrefixAndValues(prefix, message, ...) / logWithValues(message, ...) — mit printf-Formatierung.
  • logHeader(header) / logDividingLine() — optische Trennlinien/Überschriften im Log.
  • logHex(data, size) / logHexWithPrefix(prefix, data, size) — Hex-Dump ohne Farbcodierung.
  • color(colorCode = 0) — setzt die Ausgabefarbe manuell (0 = zurücksetzen).
  • indentUp() / indentDown() / indent(x) — wie die Makros, aber ohne log-Präfix im Namen.
  • checkTrace(prefix) — prüft, ob ein Prefix laut Trace-Filterliste durchgelassen wird (nur mit OPENKNX_TRACE).
  • printPrompt(), logOpenKnxHeader(), printTimestamp(), buildUptime(), buildPrefix(prefix, id) — Hilfsfunktionen für Konsole/Header-Ausgaben.

Beispiele aus dem Projekt

src/1BS_Telegram.h — freie Funktion

handle_1BS() ist eine freie inline-Funktion ohne this, daher logDebug() mit explizitem Prefix "1BS":

logDebug("1BS", "Profil: 1BS - %u", ParamENO_CHProfilSelection1BS);
...
logDebug("1BS", "D5-00-01 detected: 1BS State: %u, Output KNX: %u",
          l1bsTlg_p->u81bsTelData.State, bvalue);

src/EnoceanChannel.cpp — Klassenmethode

EnoceanChannel::check_Eno_ID() ist eine Methode von EnoceanChannel : public OpenKNX::Channel, welche logPrefix() überschreibt — daher logHexDebugP() ohne expliziten Prefix:

logHexDebugP(&pPacket->u8DataBuffer[2], 4);  // ersetzt 7 Zeilen manuellen HEX-Print-Loop

In setup() derselben Klasse werden zudem alle drei Text-Level demonstriert:

logInfoP("setup");
logIndentUp();
logDebugP("debug setup");
logTraceP("trace setup");
logIndentDown();
